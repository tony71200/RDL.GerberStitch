1. 2026-08-07 (nhánh Ver01) — Cờ chọn chế độ sinh model HALCON

Core Phạm vi: GerberStitching.Core — không đụng façade

Vấn đề

Khối code ghi .ncm/.shm trong SampleTileGenerator.cs đang bị comment, và không có file model nào tồn tại trên đĩa trong toàn bộ dataset Phase 0. Các run vẫn chạy đúng vì HalconShapeModelProvider.GetOrCreate tự CreateShapeModel trong bộ nhớ khi không tìm thấy file. Điều này lật giả định của roadmap (Master sinh model sẵn, ghi ra ổ chia sẻ cho Worker đọc).

Quyết định

Không chọn cứng một phương án — thêm cờ cấu hình để người dùng chọn theo từng lần chạy, và ghi lại lựa chọn vào sample_manifest.json để Worker biết manifest có kèm model hay không.

File đã đổi

  • GerberStitching.Core/Configuration/GerberSampleConfig.cs — thêm enum SampleModelGenerationMode { OnTheFly = 0, Pregenerate = 1 } + property ModelGeneration, default OnTheFly
  • GerberStitching.Core/Models/SampleManifest.cs — thêm [DataMember(Order = 17, EmitDefaultValue = false)] public string ModelGeneration
  • GerberStitching.Core/Imaging/SampleTileGenerator.cs — bỏ comment khối sinh .ncm/.shm, đặt sau cờ pregenerateModels; BuildManifest tra nccMetadata null-safe (chế độ OnTheFly không có metadata)

Điểm cần lưu ý

  • Default OnTheFly giữ nguyên hành vi hiện hành — không hồi quy với các run Phase 0 đã kiểm chứng.
  • Pregenerate chỉ ghi model cho tile ContentClass == Matchable — tile rỗng/low-texture không có model, đúng ý đồ (tạo shape model trên vùng không có nội dung là vô nghĩa).
  • Manifest cũ (sinh trước thay đổi này) không có trường ModelGeneration → đọc ra null, hiểu là OnTheFly. Tương thích ngược.
  • Chưa đo được mức tiết kiệm thời gian của Pregenerate tại thời điểm này — xem entry 4 để biết khi nào được xác nhận field này hoạt động đúng bằng dữ liệu thật.

2. 2026-08-07 (nhánh Ver1_0) — Thực thi Task 1.1 + 1.2: façade thật

Facade Phạm vi: RDL.GerberStitch.csproj, Facade/AlignStitchConfig.cs, Facade/GerberStitchFacade.cs

Bối cảnh

docs/Phase1_Task01.md và docs/Phase1_Task02.md trước đó chỉ là kế hoạch (façade còn là stub rỗng, internal). Lượt này thực thi thật, tham khảo trực tiếp code sản xuất trong repo GerberViewer:

  • GerberViewer/Views/AlignStitchingControl.cs — hàm RunWorkflowAsync (nhánh full workflow) → mẫu cho RunAlignStitch
  • GerberViewer/Views/CreateGerberSampleControl.cs — hàm PrepareCurrentSampleAsync + gọi SampleTileGenerator().GenerateAsync → mẫu cho GenerateSampleManifest

Task 1.1 — sửa .csproj

  • RDL.GerberStitch.csproj: hint path HALCON → $(HALCONROOT)\bin\dotnet35\... (bỏ đường dẫn máy cá nhân C:\Users\USER\...), Private=False; gộp LangVersion=7.3 lên PropertyGroup chung; thêm <Reference Include="System.Drawing" /> (thiếu — cần cho Bitmap/Size/ImageFormat trong façade)
  • GerberStitching.Core.csproj: cùng thay đổi hint path + Private=False cho halcondotnetxl/hdevenginedotnetxl

Task 1.2 — nội dung façade

GerberStitchFacade đổi internal → public sealed, thêm 2 hàm chính: GenerateSampleManifest (render Gerber → crop tile → manifest) và RunAlignStitch (Align→PoseGraph→Stitch cho cả lô).

3 quyết định thiết kế khác kế hoạch cũ (phát hiện khi đọc code tham khảo, không phải tự chọn):
  1. Không tạo DTO ảnh thủ công. Core đã có Arrangement.CapturedImageLoader.Load(imageFolder, manifestPath, w, h) — tự đọc manifest, natural-sort tên file, ghép theo vị trí index với manifest.Tiles, validate đủ (số lượng khớp, không trùng khoá, kích thước ảnh khớp nhau). RunAlignStitch vì vậy nhận thư mục ảnh (string), không nhận IList<DTO> tự chế.
  2. Không tạo DTO grid config riêng. GenerateSampleManifest nhận thẳng GerberViewer.Stitching.Configuration.GerberSampleConfig của Core — DTO thuần dữ liệu, an toàn để chạm trực tiếp. Đánh đổi: façade lộ 1 kiểu của Core (hơi ngược AGENTS.md §3.1) — chấp nhận có chủ đích.
  3. Publish bằng RunOutputLifecycle.Publish/Cleanup có sẵn trong Core (Stitching/RunOutputLifecycle.cs) — không tự viết lại pattern .creating\ → di chuyển ra thư mục cuối.

Giữ tên AlignStitchConfig, không đổi thành RdlAlignStitchOptions

Kế hoạch cũ (từ phiên trước) định đổi tên để tránh trùng GerberViewer.Stitching.Models.AlignStitchConfig của Core. Thực tế giữ nguyên — vì lớp được khai báo ngay trong namespace RDL.GerberStitch.Facade, tên trần AlignStitchConfig trong project này luôn phân giải về lớp façade (name lookup ưu tiên namespace bao quanh trước using-directive) — không lỗi CS0104 miễn mapper nội bộ viết đủ tên GerberViewer.Stitching.Models.AlignStitchConfig khi cần chạm kiểu của Core. Đúng cách AlignStitchingControl.CloneConfigForRun đã làm trong code gốc.

Bẫy ConfigVersion — đã né đúng cách

AlignStitchConfigMapper.EnsureComposite chỉ thoát sớm khi ConfigVersion >= 3; object mới có ConfigVersion = 0 (default int), khiến nhánh migration 0/1 chạy và ghi đè options cấu trúc bằng field phẳng legacy (2 bộ default lệch nhau — vd MaxAbsRotationDeg: cấu trúc 0.5° vs phẳng 0.1°). Cách làm đúng, xác nhận qua đọc AlignStitchConfigMapper.CloneForRun (dòng 187-233 — chính production cũng đặt ConfigVersion = 3 ở cuối CloneForRun):

var baseConfig = new GerberViewer.Stitching.Models.AlignStitchConfig { ConfigVersion = 3 }; // TRƯỚC mọi thứ khác
baseConfig.Input.ManifestPath = manifestPath;
// ... áp override ...
AlignStitchConfigMapper.EnsureComposite(baseConfig);
return AlignStitchConfigMapper.CloneForRun(baseConfig, outputPath); // tự đặt lại ConfigVersion=3 + SyncLegacy

Đếm tile: dùng States, không dùng TileReports

Run tham chiếu Phase 0 có TileReports.Count = 85 nhưng chỉ 80 tile thật — nghi ngờ tile qua Neighbor Recovery bị ghi report 2 lần. GerberStitchFacade.MapResult dùng AlignStitchWorkflowResult.States (không dùng TileReports) để đếm — đã xác nhận đúng bằng dữ liệu thật ở entry 3 (States cho đúng 80 phần tử, không dư).

LỗiNguyên nhânCách fix

Harness tự thêm packages.config (OpenCvSharp4.runtime.win) + <Import> props/targets, giống RDL.GerberStitch.csproj — cách NuGet chính thống, không phải hack.

Lỗi gặp phải & cách fix

LỗiNguyên nhânCách fix
CS0012: 'GerberSampleConfig' is defined in an assembly that is not referenced. You must add a reference to 'GerberStitching.Core' — xảy ra ngay cả khi harness chỉ truyền null cho tham số đó Dự định ban đầu: gọi facade.GenerateSampleManifestFromRaster(rasterPath, null, ...) từ harness để tránh phải reference GerberStitching.Core, giữ ranh giới façade thuần cho harness. Không hoạt động — C# yêu cầu assembly định nghĩa một type xuất hiện trong signature của method đang gọi phải được reference trực tiếp lúc biên dịch, bất kể có truyền null hay không. Đây là hành vi chuẩn của compiler, không phải hạn chế riêng của project kiểu cũ. Thêm <ProjectReference> từ harness tới GerberStitching.Core.csproj trực tiếp.
